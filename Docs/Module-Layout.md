# Module layout contract — version 14

Every module uses the host's `Screen` / `WidgetForm` presentation. The November 2, 2026 fullscreen and cache-list references define the shared proportions. Modules supply content and actions; they do not construct independent page layouts.

- Graph modules use two arrangements based on readable space. The graph stays above the list in small windows, including the initial 700 × 490 window and moderately enlarged floating windows. Side-by-side starts at a 944-point page viewport (approximately a 966-point outer window): 440 points for the list, 420 for the graph, the 24-point gap and shared side margins. Height alone cannot enable side-by-side. This applies only to a module's main page with a hero graph; drill-downs, Settings, Debloat and Siri & Apple Intelligence keep their existing list behavior.
- In the side-by-side arrangement, one ordered list occupies approximately 34% of available content, with a minimum of 440 points and maximum of 820 points. The graph takes the remaining width after the 24-point gap. Its top aligns with the actual top of the first list's background shade, below that list's header, using the measured header height and the existing header-to-shade spacing. This alignment follows header geometry rather than a fixed offset. The page uses its available width inside the shared side margins. Graph height responds to its width and available window height. The left list has its own vertical scroll view; the graph and its legend are fixed siblings on the right and remain in place while the list scrolls. The graph is rendered once and stays interactive. The graph initially aligns to the first list shade and retains that position after the list scrolls. Small/stacked views keep a single normal scroll view containing the graph, legend and list, so all of them scroll together. The shared page header and action dock remain fixed in both arrangements.
- During a wide module's initial scan, when no overview content is available, the loading graph spans the full content width inside the existing side margins. Its height is already the final right-pane graph height and stays unchanged through loading and the width transition. The same graph view remains mounted when data arrives. The host resizes it into its normal right-hand position with `ChartMotion.finishAnimation`, using the existing loading-finish spring, bounce and playback speed. At the spring's logical arrival, without waiting for residual bounce to settle, the existing `PageItemReveal` / `PageGroupShade` list cascade starts from its own first item. The separate list pane does not wait through the legend's stagger; compact pages keep their shared legend-then-list cascade. No new animation style or timing is introduced. Refreshes with existing list content keep the normal fixed-graph layout. Small/stacked views retain their current behavior. Interrupted loads invalidate obsolete reveal completions; Reduce Motion applies the final layout immediately.
- Page navigation uses the same `Theme.push` spring and slide/fade at every width. The host resolves the complete page in one geometry group before applying navigation, including module/settings swaps and folder/group pushes and Back. The list, graph and legend move as one page; fixed graph placement applies only to list scrolling. Child layout and value animations must not independently animate page placement. Loading's width resize and detail cascade remain tied to the loading state, rather than replaying because a page opens or becomes uncovered.
- Other adaptive pages use a centered canvas of approximately 80% of a wide window (up to 1,608 points), with 24-point gaps and at least 420 points per column. Half-screen and quarter-screen windows reclaim the side margins and reduce to two or one column. Row groups retain their ordering and stay together. There are no independent column scrollbars.
- `Screen.layout = .singleColumn` keeps settings-oriented modules in one centered list, up to 820 points wide. Debloat and Siri & Apple Intelligence use it. Settings and all its subpages use the exact same host width calculation and margins as these single-column modules (820 points maximum). Drill-downs use the same width. A missing layout field decodes as adaptive behavior.
- The host expands overview groups in place when they fit: up to 24 immediate rows in a readable column, eight below 420 points. Each group retains its title, count, total, item sizes, badges, Finder paths and actions. Longer inventories and deeper groups remain navigable, with their original complete data and identifiers.
- Selection groups remain on their dedicated page, including System Data app caches, whether or not their choices are saved. The front page shows the entry, count and total; opening it reveals the full list with section and row checkboxes, the selection action and its confirmation.
- Item and switch descriptions remain exclusively in the ⓘ information popover at every width. The host must never replace the icon with text underneath a row. Sizes, counts, state badges, actions and file locations remain on the row.
- Sections declare `SectionWidget.priority`: `.actionable` sorts ahead of `.normal` (or absent metadata), independently of the section's localized title or source position. Equal priorities retain source order. Free now uses `.actionable` in every storage module. The host keeps that section intact in the first list slot: top left beside the graph in an enlarged graph module, or first beneath the graph at the initial size. Other groups follow in stable order; selection groups inside Free now remain navigation rows.
- Graph annotations have a hard maximum of two lines total: one line for the name and one for its size. Long names truncate rather than gaining a third line. Outside-chart legend entries are indivisible single lines: marker, label and figure stay together. A measured flow layout wraps whole entries onto additional rows rather than wrapping their text or forcing equal-width columns. Only an entry wider than the entire graph may truncate its label; the figure remains visible and the complete text is available on hover. The chart, total and legend move together as one group during page navigation. Local value animations must not suppress the parent page transition; wide-page list scrolling still leaves the chart and legend fixed.
- Row action flags (Free, Delete, Uninstall, progress and outcomes) match public v1.1.5: with a size, the flag follows the title/information/Finder/badge cluster; without a size, it occupies the right edge.
- One main action remains pinned at the bottom. Confirmation, permission checks, refresh behavior, selection IDs, and cleanup semantics are unchanged by reflow. Resizing does not reset saved selections or replay the initial content cascade.
- Window corner behavior belongs to the host. Floating windows use the configured design radii. A macOS side tile, quarter tile or filled window uses the native window radius, resolved with AppKit's public concentric-corner API. A true full-screen Space uses the system's square outer boundary. Dashboard widgets use a 10-point radius while attached; grouped row surfaces use 10 points in every mode.
- Corner changes interpolate over 0.32 seconds in both directions. Window clipping, border, backdrop, zooming cards, tile fills, press overlays and shadow paths share the same state. State is per window and updates on moves, resizes, screen changes and full-screen transitions. Reduce Motion suppresses interpolation. Shadow paths and their transparent cutout follow the same interpolated radius and current frame as the glass; they must not start a separate radius animation. Resizes retire stale path animations, visibility fades only when the attached/floating state changes, and duplicate geometry notifications must not replay old corner states.

The SDK version is 16. It includes page-wide `Screen.selection`, stable `Selection.scope` and `ListWidget.fillsRemainingSpace` alongside lazy pages and native app icons. Additive optional segment kind metadata distinguishes folder destinations from file collections; optional segment selection supplies a file block’s batch action without adding a hidden selection to its overview. `Selection.partial` defaults to false when absent. The public Swift model layout changed, so all bundled module manifests use version 16; incompatible external modules are rejected before loading. Older saved screen JSON remains readable.

Verification covers layout boundaries, non-origin displays, every side and quarter with macOS tiling margins, false positives for floating edge windows, selection-page retention, semantic priority and stable ordering, Settings/single-list widths, row data preservation, legacy decoding, and rendered wide/half/quarter/single-column fixtures. Rendering fixtures do not execute cleanup or settings changes.

## Disk module: November 3 presentation and selection revision

SDK 14 adds progress-aware lazy pages, foreground activity suspension, optional ongoing page progress and explicit frozen-selection issues/partial scope membership. All bundled manifests use SDK 16. Older saved JSON decodes optional fields without requiring migration; incompatible module binaries are rejected.

The overview contains Apps (Uninstall apps, Unmatched app data, Installers), personal Folders and Files. Nonempty content categories follow verified Duplicate files, which is omitted when no removable verified set exists. No Recommended section or root raw-file preview appears. Content categories include Archives, Documents, Media and Other; scoped folders may also show Installers. Recognized installer formats are retained at all sizes during existing metadata collection. Managed caches, packages, developer outputs and other System Data targets remain outside ordinary personal-file deletion.

Ordinary category pages use one list with lightweight content-type headings, ordered by complete type allocation, and files ordered largest first within each type. Category/type selection spans pagination and uses the current size scope. A scoped smaller-file metadata pass retains only a bounded temporary file window, group totals and alias IDs, rather than a persistent whole-disk small-file inventory. The immediate preview has no fabricated complete totals; exact totals replace it when metadata work completes. Show smaller files and More items replace the existing page. Newly revealed files are never selected automatically. Native header checkboxes show partial membership, including off-page choices.

Real personal-folder pages show direct files by type, including small files. Subfolders stay on the map. When only descendant small files exist, nonempty content categories appear automatically. Empty, unreadable, protected, no-match and pending states have distinct text. Known standard folders use localized display names only at their real standard paths.

Folder tiles navigate normally. File and Other files destinations focus or reveal the existing direct list without adding a breadcrumb. A focused file is included even outside the initial bounded window. Other folders remains a map of precisely its represented folders, including nested and empty aggregates, with meaningful folder rows alongside it. The shared circular top-right Refresh supports both module and storage entry points and scopes synthetic refreshes to represented folder destinations. Refresh keeps existing content and uses the shared progress/action treatment.

Eligibility, visible checkbox membership and original review identities publish with page data. Explicit choices survive Back, categories, folders, pagination and leaving/returning during the app session. Frozen disk-backed versions retain exact allocation, count and review evidence. The host receives bounded visible membership; no fixed total-selection limit exists. Unavailable selections remain explicit, block removal and can be unchecked inline without a separate review page. Late navigation, selection and refresh replies cannot replace accepted state.

Every eligible verified duplicate copy is selectable; there is no permanently protected alphabetical keeper. Set headings use a representative filename, full copy count and total allocated size. Each copy retains its actual filename and concise location. The page separately identifies potential removable allocation; the action uses selected allocation. Selecting every copy preserves those choices and reports a survivor conflict. This check uses the complete frozen selection, including ordinary categories and other pages. Preflight resolves an unselected eligible verified survivor, preserves the selected file's original identity/digest, rehashes both contents and checks the survivor identity again immediately before each removal. No Compare button or preselection exists.

App discovery and ownership preparation complete before the module reports ready. Root, Applications and app-data pages consume the same global authoritative inventory; a folder-map projection cannot overwrite app measurements. Missing measurements remain pending or retain previously completed values, rather than becoming false zero counts/sizes. App management remains scoped where correspondence is known and explicitly global for unmatched data.

Initial indexing and duplicate verification share monotonic loading progress. Lazy metadata work uses the same Loading pill with reported percentages while retaining current rows. A completed Disk tile never requests five-second polling. Foreground-only automatic reads stop when the app loses focus or its window closes; Disk cancels optional scans/hashing/browsing, stops filesystem watching and replays persisted events on return. No ordinary background activity is inferred to be user-authorized cleanup. Explicit cleanup lifecycle tasks retain their own behavior.

SQLite stores folder paths once with integer parent IDs and necessary file metadata. Native indexing uses up to eight workers, bounded buffers and serialized writes. New index generations publish atomically after completion; interrupted initial collections retry without treating partial batches as ready. Hardlinks count allocation once and collapse before content hashing. Samples reject nonmatches before full hashing; unchanged identity-bound fingerprints are reused. Missing/unreadable content is unknown, never unused. Duplicate metadata projections and selected batches remain bounded in Swift.

Ordinary removal remains unprivileged, enforces positive personal roots, original identities, no-follow descriptors and current-use checks. Permanent deletion is the default; optional Trash mode must match its frozen confirmation. App uninstall retains privileged exact-plan validation. Unmatched-data deletion retains its separate bounded recursive preflight and recovery manifest. System Data remains the owner of its cleanup targets and publishes typed post-action target measurements without unrelated global settling delays.

App, window, screenshot and visual verification is performed by the user. Code-level checks exclude native rendering/window tests. Synthetic performance measurements are reported separately from production disk or live app measurements.

Folder navigation is explicitly independent of duplicate discovery: opening a folder, a nested folder or the cached duplicate page must never start an all-size subtree crawl or content hashing. Ordinary navigation also reuses the ready global app inventory. Direct-file metadata reads only the requested directory. Recursive review queries use bounded indexed personal-root ranges; a protected/managed scope with no eligible inventory completes immediately. Preview limits include all visited folders, including excluded folders. Production-scale cache navigation is covered by an opt-in test against an isolated index copy, with no app/window interaction.

## Final navigation, folder inventory and duplicate header revision

SDK 15 adds optional list-heading count/size metadata. File-type and duplicate-set titles are outside shaded file-row lists; they never appear as selectable file rows. Existing file and select-all control styles remain shared with other modules.

Cached page transitions never create loading state merely because a page was requested. Lazy progress appears only when a module reports actual work, and page completion invalidates late progress callbacks. Ongoing scoped metadata is followed through the page channel without running an unrelated whole-module reconciliation. Installers use the already collected all-size installer inventory even when an older destination carries `includeSmaller`; opening that page does not start a recursive small-file worker.

Folder lists combine reviewable direct and descendant files instead of letting one direct metadata file suppress descendants. Cached large-file results appear first when available; otherwise bounded scoped smaller-file metadata supplies the list. A folder's smaller expansion/pagination keeps its map and breadcrumb context. Ordinary nested images contribute to the parent inventory. Photo-library packages remain a separate read-only inspection destination with Finder access; their contents never enter ordinary file selections or deletion. No broad package-deletion exemption is introduced.

Duplicate header Select All selects the removable subset of each complete displayed set, leaving one currently unselected verified survivor. Two copies select one for deletion; larger sets select all but a survivor. Prior manual choices are preserved, including a manually selected alphabetical first copy. An open but verified unselected copy can be the survivor. The full scope includes off-page members; header completion and clear operations use per-set semantic membership against the accepted frozen version. Manual all-copy or cross-category conflicts still block removal until corrected.

Identical byte contents can legitimately exist under different names in the same folder. Duplicate cleanup excludes project resources when actual ancestor manifests, Git/worktree markers, Xcode project/workspace siblings or asset-catalog structure establish project context. This policy applies to discovery, cached results, selection resolution and fresh execution checks, without expanding or shrinking ordinary explicit personal-file review authority. A manifest downloaded directly into a standard personal root does not classify the entire root as project content. Custom project formats without recognizable evidence remain a limitation.

Complete duplicate scope streaming prepares the verified relation once, uses indexed disk-backed candidate groups and bounded Swift batches, and does not rebuild the full projection for every 200 displayed members. Selected and surviving content is reverified during preflight; the actual proof is stored on disk for the action and reused unchanged at execution. A disappearing survivor cannot be silently replaced after preflight. Duplicate row, set and selected sizes consistently use allocated space.

## Settings, replacement transitions and Finder placement follow-up

Disabling Disk removes its dashboard destination, rejects storage/module navigation and suspends its optional work. Opening the disk gauge must never silently re-enable the setting. Returning from Settings cannot reopen a disabled module. Foreground/visibility callbacks and superseded refreshes cannot resume a disabled module.

Show smaller files and More items replace the current page at the same breadcrumb depth with a new transition identity, using the standard page-change animation. Visible checked membership is resolved without a complete category-selection scan before navigation. A stale page follower cannot overwrite a newer replacement. Scoped folder snapshots are bounded and reused until their relevant data changes.

Ordinary type pages have their type list headings only, with no empty main-category selection heading. The first shaded list therefore aligns naturally with the graph. Duplicate pages retain their explicitly requested whole-scope safe Select All control. Disk no longer adds folder-location text badges; each row retains its Finder path/control.

Visible personal-folder rows show direct entry counts (files and subfolders, including ordinary small files) after the title and allocation on the right. New scans collect counts in the existing native metadata pass. Legacy counts are read from only the visible root directory and cached per index revision; the large-file detail count is never substituted for total folder items. Newly collected counts persist as optional directory metadata.

The user requested an app-wide placement experiment: the Finder/open-folder icon is the final row control after the size and navigation chevron, including navigable groups. This change is confined to the shared WidgetView row/header renderer and can be reverted without changing module inventories or cleanup behavior. Informational and action controls retain their existing roles.

## Checkbox feedback and deletion completion

Checkbox changes keep the existing Free selected pill. Visible per-file toggles project count, checked state and allocation immediately while immutable backend edits remain serialized. Pending estimates never authorize destructive execution; the action callback requires all edits to be accepted first. Once committed, the authoritative token replaces the estimate. Passive metadata/refresh progress cannot replace an existing selected-size action with Loading. Actual removal continues to use the normal working state.

Deletion progress must not schedule reads of the old selected token: bulk membership keys and membership refreshes are suspended while removal or its post-action presentation is running. Stale membership responses cannot turn removed targets into a files-changed warning. Complete preflight identity, eligibility, mode, current-use and duplicate-origin survivor checks remain mandatory.

SDK 16 adds optional `ActionResult.removedBytes`, the verified allocated size of successfully removed file targets. This differs from `freedBytes`, measured volume reclamation. Disk file completion counts the removed allocation with a localized “removed” label, including files removed from the original location into Trash. Other cleanup completions retain their existing “freed” count. Failed targets do not contribute to the removed total; actual volume measurements remain distinct for cleanup history.
