# Module layout contract — version 17

Every module uses the host's `Screen` / `WidgetForm` presentation. The November 2, 2026 fullscreen and cache-list references define the shared proportions. Modules supply content and actions; they do not construct independent page layouts.

**Mandatory app-wide heading rule:** list, section and selection-group headings contain the group name only. Counts, sizes, totals and percentages are prohibited both inside the title string and beside it. This applies to every module, overview, expanded group and drill-down, at every window size. `ListWidget` has no quantity subtitle/trailing fields. The renderer must not promote `Row.subtitle` or `Row.trailing` into a heading. Measurements remain on item/navigation rows, chart figures, selected-action labels and confirmations. A meaningful filename containing numbers is still a name, not an appended measurement.


**Dashboard context menus:** right-click anywhere on a module widget (graph, caption, switch, or empty ground) opens one menu with Refresh and, when the module supplies `Tile.freeAction`, Free. The dashboard suppresses per-element Finder/Delete menus. Refresh explicitly reloads the owning module; the Apps and Files gauge also refreshes volume measurements. Free runs the module's declared cleanup with its normal confirmation, permission checks, progress and outcome handling. It is never inferred from a localized title or an unrelated page action such as Restart or Enable. Missing `freeAction` in old saved tiles means Refresh only. Settings is not a module and has no cleanup/refresh menu.

**Module context menus:** inside a module, graph elements and file/folder rows support their element-specific `GraphContextActions`: Open in Finder for declared paths, Delete for a declared action, and Refresh supplied by the host. Delete always asks through the shared `AppAlert`, even if a module omits confirmation metadata. Paths are checked again on invocation. Busy refresh and deletion commands remain visible but disabled. Synthetic aggregates never inherit destructive actions from members. Optional context metadata and dashboard actions decode as nil in older saved presentations; this additive change retains SDK version 17.

Apps and Files presents its root categories in Apps, Files, Folders order. Folder lists provide navigation, Finder and Refresh without inline or context-menu Delete actions. Eligible folder graph blocks and an open folder’s dock retain confirmed Delete. Pages with no positive graph measurements omit the hero and use the single-column list layout, keeping empty-folder messages at the top. Confirmation names the folder, explicitly includes all contents and honors the configured Trash/permanent-deletion choice. Removal rechecks directory identity, ownership claims on ancestors and descendants, open file descriptors, local mounts, owners, flags and no-follow file types. The full bounded tree is preflighted before any mutation. Explicit personal-folder deletion removes contained symbolic links as links without following their targets, including external, broken and cyclic links; app-data cleanup retains its stricter link rejection. Failure-pill hover help includes the complete underlying reason and affected path. The home itself, managed/protected locations and app packages have no folder-delete action. Standard personal folders and custom personal folders are eligible. Partial failures preserve remaining data and refresh the affected inventory. File rows and individual file blocks expose their reviewed one-file deletion; synthetic groups have no bulk Delete.

Dashboard graphics retain their normal entrance animations, including when remounted during a module’s closing zoom. Blocks, dots, feature meters and the disk gauge start through their existing appearance motion rather than being initialized fully drawn. Active block scans and cleanups keep the geometric loading sequence; Reduce Motion retains its existing behavior. The shared tile/zoom renderer mounts every returning graphic at the moment Back begins, even while its opacity is still zero. The return fade runs across the full shrinking movement, so an entrance begins while its widget moves rather than mounting during the final 35% and catching up after landing. Opening still releases the graphic once the page covers it. The rule depends only on transition direction and applies to every module and graphic type; there are no module-specific animation paths. During a closing zoom the graphic is also laid out once at its resting tile dimensions and transformed to the card’s current bounds. The background, caption and card retain their own geometry; the graphic’s internal entrance springs no longer chase a changing layout. At the final frame its transform is exactly identity. This shared path covers blocks, dots, states and gauges and leaves ordinary dashboard layout and opening unchanged. A release-mode synthetic 1,000-item chart replay over 121 zoom sizes measured 121 geometry preparations before versus one after, with measured geometry work falling from approximately 825 ms to 9 ms. This is a code-level workload comparison, not a measured UI frame rate; final geometry is asserted equal to the normal tile.

Height alone cannot enable side-by-side. This applies only to a module's main page with a hero graph; drill-downs, Settings, Debloat and Siri & Apple Intelligence keep their existing list behavior.

Its top aligns with the actual top of the first list's background shade, below that list's header, using the measured header height and the existing header-to-shade spacing. Refreshes with existing list content keep the normal fixed-graph layout. Small/stacked views retain their current behavior. - Page navigation uses the same `Theme.push` spring and slide/fade at every width. The list, graph and legend move as one page; fixed graph placement applies only to list scrolling. Child layout and value animations must not independently animate page placement. Loading's width resize and detail cascade remain tied to the loading state, rather than replaying because a page opens or becomes uncovered.
- Other adaptive pages use a centered canvas of approximately 80% of a wide window (up to 1,608 points), with 24-point gaps and at least 420 points per column. Half-screen and quarter-screen windows reclaim the side margins and reduce to two or one column. Row groups retain their ordering and stay together. There are no independent column scrollbars.

A missing layout field decodes as adaptive behavior.
- The host expands overview groups in place when they fit: up to 24 immediate rows in a readable column, eight below 420 points. Each group retains its name; item/navigation rows retain counts, totals, item sizes, badges, Finder paths and actions. Counts/totals must never be promoted into the group heading. Longer inventories and deeper groups remain navigable, with their original complete data and identifiers.
- Selection groups remain on their dedicated page, including System Data app caches, whether or not their choices are saved. The front page shows the entry, count and total; opening it reveals the full list with section and row checkboxes, the selection action and its confirmation.
- Item and switch descriptions remain exclusively in the ⓘ information popover at every width. The host must never replace the icon with text underneath a row. Sizes, counts, state badges, actions and file locations remain on the row.
- Sections declare `SectionWidget.priority`: `.actionable` sorts ahead of `.normal` (or absent metadata), independently of the section's localized title or source position. Equal priorities retain source order. Free now uses `.actionable` in every storage module. The host keeps that section intact in the first list slot: top left beside the graph in an enlarged graph module, or first beneath the graph at the initial size. Other groups follow in stable order; selection groups inside Free now remain navigation rows.
- Graph annotations have a hard maximum of two lines total: one line for the name and one for its size. Long names truncate rather than gaining a third line. Outside-chart legend entries are indivisible single lines: marker, label and figure stay together. A measured flow layout wraps whole entries onto additional rows rather than wrapping their text or forcing equal-width columns. Only an entry wider than the entire graph may truncate its label; the figure remains visible and the complete text is available on hover. The chart, total and legend move together as one group during page navigation. Local value animations must not suppress the parent page transition; wide-page list scrolling still leaves the chart and legend fixed.
- The app-uninstaller list uses normal-height checkbox rows with 18-point native icons and no information popover. A live In use pill follows workspace launch/termination notifications. Review groups each app above its app-data category rows. Apps selected on the preceding page remain included in uninstall. The app-data heading checkbox selects or clears all eligible items in that list, with a mixed state for partial selection; it does not hide the list or toggle app removal. Category checkboxes select eligible locations; the category title opens their details with the same selection scope. Only verified exclusive caches are preselected (within the existing 32-location data-removal bound); support data, settings and containers stay unchecked. Zero-byte optional data is omitted; mandatory startup cleanup remains visible. The action total and confirmation include checked apps and their checked data only. Finder controls follow size text at the right edge throughout the app.
- Uninstall asks the selected installations and their embedded running apps to quit normally, then waits before removing any app data or bundles. A cancelled save/quit or timeout preserves the targets and reports that the apps remain in use. Normal writes inside the same selected directory during quit are refreshed before removal; replaced roots and changed individual settings files require another review. Matching uses installation paths so another copy with the same bundle identifier is left alone.
- One main action remains pinned at the bottom. Confirmation, permission checks, refresh behavior, selection IDs, and cleanup semantics are unchanged by reflow. Resizing does not reset saved selections or replay the initial content cascade.
- Window corner behavior belongs to the host. Floating windows use the configured design radii. A macOS side tile, quarter tile or filled window uses the native window radius, resolved with AppKit's public concentric-corner API. A true full-screen Space uses the system's square outer boundary. Dashboard widgets use a 10-point radius while attached; grouped row surfaces use 10 points in every mode.
- Corner changes interpolate over 0.32 seconds in both directions. Window clipping, border, backdrop, zooming cards, tile fills, press overlays and shadow paths share the same state. State is per window and updates on moves, resizes, screen changes and full-screen transitions. Reduce Motion suppresses interpolation. Shadow paths and their transparent cutout follow the same interpolated radius and current frame as the glass; they must not start a separate radius animation. Resizes retire stale path animations, visibility fades only when the attached/floating state changes, and duplicate geometry notifications must not replay old corner states.

The SDK version is 19. It includes page-wide `Screen.selection`, stable `Selection.scope` and `ListWidget.fillsRemainingSpace` alongside lazy pages and native app icons. Additive optional segment kind metadata distinguishes folder destinations from file collections; optional segment selection supplies a file block’s batch action without adding a hidden selection to its overview. `Selection.partial` defaults to false when absent. The public Swift model layout changed, so all bundled module manifests use version 19; incompatible external modules are rejected before loading. Older saved screen JSON remains readable.

Verification covers layout boundaries, non-origin displays, every side and quarter with macOS tiling margins, false positives for floating edge windows, selection-page retention, semantic priority and stable ordering, Settings/single-list widths, row data preservation, legacy decoding, and rendered wide/half/quarter/single-column fixtures. Rendering fixtures do not execute cleanup or settings changes.
